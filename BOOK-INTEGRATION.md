# How this companion should strengthen the book

The book is now a two-part edition (Edition 5, November 2026): Part 1 is a short beginner path with a runnable lab, Part 2 is the deeper healthcare case. Living updates are in LATEST.md. The companion carries exercises, detailed
implementation and reproducible evidence. Do not claim a new book revision has
been published until its references and PDF have actually been updated.

## Replace rather than append

- Compress repeated boundary disclaimers into a clear scope statement and local
  notes where a distinction changes the implementation.
- Replace one generic discovery page with the domain learning cycle and evidence ledger.
- Replace one repeated communication objection with the English practice ladder
  and a before/after explanation.
- Add the stale-approval interleaving beside the architecture decision. Link the
  runnable example and show exactly what the local transaction proves.
- Replace a generic evaluation page with a measured comparison only after the
  experiment exists. Until then label it a protocol, not a result.
- Connect the five-layer lens to the existing Harness Engineering repository.
  Identify coding-agent controls separately from application-runtime controls.
- Replace vague product assertions with a verified Kodiflex failure-and-fix story
  when the team supplies evidence it can disclose publicly.

Each chapter should end with: one artifact to produce, a challenge, a worked
answer, a legitimate source and the corresponding repository path. Use one stable
GitHub release tag for the printed edition, so exercises do not drift after printing.
The repository landing page may evolve; a print-specific tag must remain stable.

## Proposed completion gates

1. **Foundation:** existing synthetic lab, domain/system-design/communication modules,
   source links and local checks. Implemented in this starter.
2. **Engineering depth:** richer cases, stronger baseline, fixed model workflow and
   reproducible live evaluation. Not yet implemented or measured.
3. **External challenge:** domain practitioner and experienced developer reviews,
   with documented disagreements and resulting changes. Not yet obtained.
4. **Publication:** public repository, verified CI, chosen reuse terms, tagged release,
   book QR updates and physical print proof. Pending.

Success is a reader who can run, question and explain the evidence. A larger
repository or a longer bibliography does not by itself establish that success.
